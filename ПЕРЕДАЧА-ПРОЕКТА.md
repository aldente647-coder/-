# Голосовой соцмониторинг — передача проекта

Состояние на 08.11.2026. Начинать знакомство с проектом с этого файла.

Это открытая копия проекта: без технического задания Заказчика, адресов
рабочих серверов и внутренних документов.

**Коротко:** программная часть готова и проверена: анкета, движок интервью,
распознавание и синтез речи, Asterisk, база, взвешивание, индекс, кабинет,
выгрузки. **Не было ни одного звонка живому человеку** — нет подключения
к IP-телефонии (SIP-транка). После подключения остаются две доработки
кода до массового обзвона — они перечислены в разделе 5.

---

## 1. Что это

Голосовой робот обзванивает жителей, проводит короткое интервью по
утверждённой анкете (7–10 минут), записывает ответы. Дальше система
взвешивает выборку, считает индекс социального напряжения, разбирает
открытые ответы по темам и собирает отчётность для Заказчика.

Три правила, на которых построено всё остальное:

* **Языковой модели в разговоре нет.** Ход беседы определяют граф анкеты
  и грамматики ответов. Не разобрал — переспросил один раз и поставил код
  «нераспознанная речь», а не догадку (ТЗ §8.2).
* **Всё работает на своём сервере.** Распознавание и синтез речи локальные,
  наружу ничего не уходит (ТЗ §14.1).
* **Номер отделён от ответов.** Телефоны зашифрованы, поиск — по слепому
  индексу, ответы лежат в другой схеме базы и с номером не связываются
  (ТЗ §14.2).

## 2. Как проходит один звонок

```
 Диалер ─ берёт номер из очереди волны (окна времени, повторы, стоп-лист)
   │       выбирает исходящий номер из карусели, следит за темпом набора
   ▼
 Asterisk ─ набирает через SIP-транк: PJSIP/<номер>@trunk  (ARI originate)
   │        AMD отличает человека от автоответчика
   │        канал входит в приложение Stasis «socmon»
   ▼
 Мост звука ─ Asterisk подключает к каналу внешнее медиа по AudioSocket:
   │          TCP, 8 кГц, голос абонента без перекодирования
   ▼
 GigaAM v3 ─ нарезка по паузам (VAD) → распознанная фраза
   ▼
 Движок анкеты ─ грамматика узла → код ответа → следующий узел
   │            перебивание, тишина, «повторите», «кто вы», отказ, перевод
   ▼
 Проигрывание ─ готовый WAV реплики (озвучен заранее), отклики «угу/понятно»
   ▼
 Запись ─ две дорожки: абонент и робот отдельно
   ▼
 PostgreSQL ─ ответы, исход по AAPOR, шкала событий звонка
   ▼
 Ночью ─ разбор открытых ответов (темы, упоминания, тональность)
   ▼
 Кабинет и выгрузки ─ взвешивание (IPF), индекс, Excel, Word, SPSS-совместимый CSV
```

Машина состояний звонка защищает от гонок и повторных событий: одно
событие не может дважды сменить состояние попытки, зависшие звонки
закрывает сторож.

## 4. Что работает

### Проверено на живом стенде (Ubuntu 26.04, Asterisk 22)

| Что | Как проверено |
|---|---|
| Asterisk, конфиги, ARI | запуск, контрольный звонок внутри станции проходит цепочку |
| Распознавание речи | GigaAM на сервере, ~4% ошибок на синтезированном голосе |
| Озвучка | все реплики четырёх волн, 8 кГц |
| Кабинет | 13 разделов, вход, роли, CSRF, отзыв сессий |
| База контактов | загрузка ~8 тыс. номеров, дубли и мусор отсеяны |
| Аналитика | волна на синтетических данных: веса, индекс, пакет выгрузок |
| Демо опроса | анкета целиком в браузере |

### Проверено только тестами

* регламент дозвона: окна времени, интервалы между попытками, стоп-лист;
* диалер: темп, карусель номеров, предохранитель на массовые обрывы;
* цикл звонка: перебивание, тишина, оклик, перевод на оператора;
* 35 сценариев нестандартных ответов («не очень доволен», «а вы кто»,
  поправки по ходу, уклончивые ответы).

Проверка 08.11.2026 на чистой машине с PostgreSQL 16: **827 тестов прошли**,
3 пропущены (необязательные инструменты озвучки), ruff и mypy strict — без
замечаний.

```bash
uv sync --all-groups --extra dev
export SOCMON_TEST_DATABASE_URL=postgresql+psycopg://<user>:<pass>@localhost/socmon_test
uv run pytest -q && uv run ruff check . && uv run mypy src
```

Без PostgreSQL тесты с базой пропускаются, остальные проходят.

## 5. Что не работает и что осталось

| # | Что | Что нужно |
|---|---|---|
| 1 | **Нет SIP-транка** | реквизиты от оператора связи или АТС — раздел 7 |
| 2 | **Ни одного живого звонка** | тестовые звонки сотрудникам; по записям подстроить паузы и пороги распознавания под реальный канал |
| 3 | **Нет запуска массового обзвона** | диалер написан и проверен, но связан только с симулятором. Нужны источник контактов из базы (реализация `ContactSource.claim`) и служба, которая крутит диалер на живом Asterisk. Одиночный звонок уже работает: `socmon calltest` |
| 4 | **Нет экрана оператора** | перевод звонка на оператора работает, интерфейса для него нет |
| 5 | **Две служебные записи** | `socmon/callback-info` (при обратном звонке) и `socmon/technical-issue` (аварийное прощание) — текст утвердить, озвучить |
| 6 | **Три показателя из анкеты** | сводные индексы Д6+Д7 и Д14+Д15, показатель Д10 для 18–50 лет |
| 7 | **Озвучка не в репозитории** | WAV в `.gitignore`. Собрать заново (`socmon voice render` / `voice realistic`) или забрать со стенда. Голоса Анна и Алексей (Qwen3-TTS, Apache-2.0) годятся для боевого использования; голоса Silero — только с платной лицензией |
| 8 | **Резервный пул номеров** | карусель номеров в коде есть, второго транка в конфиге нет |

Чего мы не знаем без живых звонков: **достижимость** (сколько людей берут
трубку и доходят до конца — на этой цифре держится вся экономика) и
**точность распознавания на телефонном канале** с шумом и сжатием.

## 6. Как развернуть

Подробно — [deploy/README.md](deploy/README.md). Кратко:

**Нужно:** Linux (Ubuntu 24.04+), Python 3.12 и `uv`, PostgreSQL 16+,
Asterisk 20+. Видеокарта не обязательна. Память — от 8 ГБ (модели
распознавания ~0,9 ГБ). Модели скачиваются при первом запуске с серверов
Сбера (GigaAM) и Hugging Face — серверу нужен туда доступ.

```bash
git clone <репозиторий> && cd voice-socmonitor
uv sync --all-groups
```

**Секреты** — в `/etc/socmon/env` (права 600), в git не кладутся:

```
DATABASE_URL=postgresql+psycopg://socmon@localhost/socmon
SOCMON_PHONE_INDEX_KEY=<openssl rand -hex 32>   # менять нельзя без пересчёта базы
SOCMON_PHONE_ENC_KEY=<openssl rand -hex 32>     # потеряете — не расшифруете номера
SOCMON_SECRET_KEY=<openssl rand -hex 32>        # сессии кабинета
SOCMON_ARI_URL=http://127.0.0.1:8088
SOCMON_ARI_USER=socmon
SOCMON_ARI_PASSWORD=<пароль ARI>
SOCMON_ARI_ENDPOINT=PJSIP/{number}@trunk
SOCMON_EXTERNAL_IP=<внешний адрес сервера>
SOCMON_TRUNK_HOST=<SIP-сервер оператора>
SOCMON_TRUNK_USER=<логин>
SOCMON_TRUNK_PASSWORD=<пароль>
SOCMON_OPERATOR1_PASSWORD=<пароль софтфона оператора>
SOCMON_MEDIA_DIR=/opt/socmon/media
```

**Порядок:**

```bash
set -a; . /etc/socmon/env; set +a
uv run alembic upgrade head                 # база
sudo -E deploy/install-configs.sh           # конфиги Asterisk (не руками!)
sudo systemctl restart asterisk
uv run socmon check src/socmon/questionnaires/wave-base.yaml   # анкета
uv run socmon voice check src/socmon/questionnaires/wave-base.yaml  # озвучка
uv run socmon simulate --numbers 200        # волна целиком без телефонии
uv run socmon useradd admin "Администратор" admin
uv run socmon serve                         # кабинет на 127.0.0.1:8000
```

Кабинет и ARI слушают только локальный адрес — наружу их не выставлять,
ходить через SSH-туннель или nginx с HTTPS.

## 7. Подключение к IP-телефонии

Это главный оставшийся шаг. Подходит любой вариант с SIP: транк оператора
связи, SIP-транк от существующей АТС организации-инициатора или наш
сервер как SIP-абонент этой АТС. Заявка для администратора АТС —
[docs/SIP-ЗАЯВКА.md](docs/SIP-ЗАЯВКА.md).

**Что получить от оператора/АТС:**

1. адрес SIP-сервера;
2. логин и пароль — или подключение по IP без регистрации;
3. разрешение на исходящие на мобильные и городские номера;
4. номер, который увидит абонент (на него должно быть можно перезвонить);
5. лимит одновременных звонков и формат набора номера.

**Подключение по логину и паролю** (конфиг уже под это написан):

```bash
# вписать SOCMON_TRUNK_HOST / USER / PASSWORD в /etc/socmon/env
set -a; . /etc/socmon/env; set +a
sudo -E deploy/install-configs.sh
sudo asterisk -rx "pjsip reload"
sudo asterisk -rx "pjsip show registrations"     # должно быть Registered
```

**Подключение по IP без регистрации:** в `deploy/asterisk/pjsip.conf`
убрать секцию `[trunk-registration]` и строку `outbound_auth` у `[trunk]`;
`[trunk-identify]` уже сопоставляет входящие по адресу АТС. Межсетевой
экран АТС должен пропускать наш сервер: SIP 5060/udp и RTP 20000–30000/udp.

**Первый звонок** — себе на мобильный:

```bash
uv run socmon calltest 79XXXXXXXXX --from <номер-для-абонента> --voice anna
```

Команда печатает ход звонка: что распознано, что записано, где робот
переспросил. Интервью сохраняется с пометкой «тестовое» и в массив волны
не попадает. Что проверять в звонке — [docs/ТЕСТОВЫЙ-ЗВОНОК.md](docs/ТЕСТОВЫЙ-ЗВОНОК.md).

## 8. План до пилота

1. Подключить транк, сделать 5–10 звонков сотрудникам, разобрать записи,
   подстроить паузы и распознавание.
2. Источник контактов из базы и служба обзвона (п. 3 таблицы раздела 5).
3. Служебные записи, экран оператора.
4. Пилот: ~50 завершённых интервью. Для этого нужно порядка 2,5–5 тыс.
   наборов — цифра 100–200 попыток из ТЗ к 50 интервью не приведёт.
5. По итогам пилота — достижимость, мощность линий, цена волны.

## 9. Правовые условия до первого массового звонка

* **Инициатор вызовов — госорган.** Только так обзвон без предварительного
  согласия абонентов законен (ст. 44.1-1 закона «О связи»). Договор
  с оператором и номерная ёмкость — на Заказчика.
* **База номеров.** Нужно законное основание её использования для опросов
  (152-ФЗ, ст. 5–6). Разбор — [docs/152-ФЗ.md](docs/152-ФЗ.md).
* **Голос робота.** Если голос клонирован с живого человека — его письменное
  согласие (голос — биометрические данные, ст. 11 152-ФЗ).
* **Вступление** честно говорит, что разговор ведёт голосовой помощник
  (ТЗ §8.4).
