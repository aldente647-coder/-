# Развёртывание стенда

Стенд — это Asterisk плюс управляющий процесс. Реальных абонентов он не
звонит: пока не решён вопрос из [RESEARCH.md §4](../RESEARCH.md) о том,
кто по документам инициатор массовых вызовов, обзвон незаконен.

Стенд нужен для другого — проверить цепочку целиком на живой АТС:
набор → события ARI → машина состояний → движок анкеты → проигрывание
реплик → раздельная запись → сохранение интервью.

> **Статус конфигов.** Проверены на живом Asterisk 22 (Ubuntu 26.04,
> 21.08.2026). Две ошибки, которые могла показать только живая АТС,
> исправлены: `noload = manager.so` валил запуск (модуль встроенный),
> а `envsubst` по всему `extensions.conf` затирал переменные дилплана,
> превращая `Stasis(${STASIS_APP},...)` в `Stasis(,,)` — канал молча
> не входил в приложение. Раскладывать конфиги следует скриптом
> `deploy/install-configs.sh`, а не руками.
>
> Прежний текст: написаны, но на живом Asterisk не проверялись.
> Синтаксис и связь с кодом стережёт `tests/test_deploy_config.py`;
> всё остальное выяснится при первом запуске. Ожидайте правок в pjsip.conf
> под конкретного оператора связи — там больше всего вариативности.

## Что понадобится

- Linux с Asterisk 20 LTS или новее (в Homebrew Asterisk нет — на macOS
  только Docker или удалённая машина);
- PostgreSQL 17 и Redis;
- публичный IP либо проброс портов: 5060/udp для SIP, 20000–30000/udp для голоса;
- SIP-транк — **опционально**. Без него стенд гоняет звонки внутри себя,
  и этого достаточно, чтобы проверить всю цепочку.

## Установка Asterisk

```bash
sudo apt update
sudo apt install -y asterisk asterisk-modules
sudo systemctl stop asterisk
```

## Конфиги

```bash
set -a; . /etc/socmon/env; set +a
sudo -E deploy/install-configs.sh
```

Скрипт подставляет секреты **только по списку переменных и только в те
файлы, где секреты есть**. Прогонять через `envsubst` весь `extensions.conf`
нельзя: `${STASIS_APP}` и `${AMDSTATUS}` — переменные дилплана, которые
раскрывает Asterisk во время звонка. Подставленные при установке, они
превращаются в пустоту, дилплан остаётся синтаксически верным, Asterisk
запускается без единой жалобы, а звонки молча обрываются.

Переменные, которые должны быть заданы:

| Переменная | Что это |
|---|---|
| `SOCMON_ARI_PASSWORD` | пароль пользователя ARI |
| `SOCMON_EXTERNAL_IP` | внешний адрес для NAT (на стенде без NAT — убрать строки) |
| `SOCMON_TRUNK_HOST` | хост оператора связи |
| `SOCMON_TRUNK_USER` | логин транка |
| `SOCMON_TRUNK_PASSWORD` | пароль транка |
| `SOCMON_OPERATOR1_PASSWORD` | пароль софтфона дежурного оператора |

**Секреты не коммитятся.** Держите их в `/etc/socmon/env` с правами `600`
и владельцем `root` — ТЗ §14.2 и §14.3 требуют разграничения доступа.

## Озвучка

Реплики проигрываются файлами (ТЗ §8.1, §8.3), Asterisk ищет их в своей
библиотеке звуков:

```bash
uv run socmon voice render --out media --voice baya
sudo mkdir -p /usr/share/asterisk/sounds/socmon
sudo cp media/*.wav /usr/share/asterisk/sounds/socmon/
sudo chown -R asterisk:asterisk /usr/share/asterisk/sounds/socmon
```

Плюс две служебные записи, которых нет в анкете, — их надо записать отдельно
и утвердить у Заказчика вместе с остальными формулировками:

- `socmon/callback-info` — информирование при обратном звонке (ТЗ §9.1);
- `socmon/technical-issue` — аварийное прощание, если управляющий процесс
  недоступен.

## Запуск

```bash
sudo systemctl start asterisk
sudo asterisk -rx "pjsip show endpoints"
sudo asterisk -rx "ari show apps"
```

Проверка ARI снаружи Asterisk:

```bash
curl -u socmon:$SOCMON_ARI_PASSWORD http://127.0.0.1:8088/ari/asterisk/info
```

ARI слушает только петлю — это намеренно. Он даёт полный контроль над АТС,
включая прослушивание каналов. Управляющий процесс живёт на той же машине
либо ходит через SSH-туннель.

## Управляющий процесс

```bash
export SOCMON_ARI_URL=http://127.0.0.1:8088
export SOCMON_ARI_USER=socmon
export SOCMON_ARI_PASSWORD=...
export SOCMON_ARI_ENDPOINT='PJSIP/{number}@trunk'
export SOCMON_PHONE_INDEX_KEY=$(openssl rand -hex 32)
export SOCMON_PHONE_ENC_KEY=$(openssl rand -hex 32)
# Одна переменная на всё: миграции, команды и кабинет читают её же.
export DATABASE_URL=postgresql+psycopg://socmon@localhost/socmon

uv run alembic upgrade head
```

> **Ключ слепого индекса менять нельзя** без пересчёта всей базы: он
> детерминированный, и на новом ключе индексы разойдутся, а дедупликация
> по номеру перестанет работать (`domain/identity.py`).

## Единая точка входа

Одна ссылка на всё: `https://<домен>/`

Гость видит два пути — послушать опрос и войти в кабинет. Вошедший
попадает сразу на сводку по волне. Демонстрация опроса открыта без
учётной записи; всё остальное требует входа.

На стенде домен получен через nip.io (он резолвится в IP сервера),
сертификат — Let's Encrypt. Для боевого контура нужен настоящий домен.

## Кабинет

```bash
export SOCMON_SECRET_KEY=$(openssl rand -hex 32)
uv run socmon useradd ivanov "Иванов И.И." customer
uv run socmon serve
```

Кабинет слушает петлю по умолчанию — как и ARI, и по той же причине:
в нём телефонные номера и записи разговоров. Наружу его не выставляют,
ходят через SSH-туннель:

```bash
ssh -N -L 8000:127.0.0.1:8000 socmon@сервер
```

Роли и что они видят:

| Роль | Номера | Записи | Управление |
|---|---|---|---|
| `admin` | да | да | всё |
| `customer` | нет | да | волны, анкеты, выгрузки |
| `analyst` | нет | нет | ничего, только цифры |
| `coder` | нет | да | ручная проверка разметки |
| `operator` | да | нет | ничего |
| `auditor` | нет | нет | ничего, только журнал |

Право видеть номер и право слушать запись раздельные: «главнее» не значит
«нужнее», и аналитик номеров не видит вовсе (ТЗ §14.2).

## Проверка до первого звонка

Всё это работает без Asterisk и без транка:

```bash
uv run socmon check                 # анкета: граф связен, все пути завершаются
uv run socmon voice check           # озвучка полная, оценка длительности
uv run socmon simulate --numbers 200  # волна целиком на подставном движке
uv run pytest -q                    # включая тесты конфигов
```

## Первый звонок внутри стенда

Без транка — софтфон, зарегистрированный как `operator1`, звонит на номер
стенда и попадает в `socmon-inbound`. Так проверяется входящая нога и запись.

Для исходящей ноги нужен либо транк, либо второй софтфон и правило маршрутизации
на него вместо `trunk` в `SOCMON_ARI_ENDPOINT`.

## Чего здесь нет

- **Распознавание речи** сделано: мост AudioSocket от Asterisk к GigaAM
  (`src/socmon/asr/audiosocket.py`), без UniMRCP.
- **Разделение контуров.** Боевой контур — только на сервере в РФ
  (ТЗ §14.1). На стенде работаем только с синтетическими данными,
  `socmon simulate` для того и написан.
- **Служба массового обзвона.** Диалер написан, но запускается только
  на подставном движке (`socmon simulate`). Живой звонок — по одному,
  `socmon calltest`. См. [ПЕРЕДАЧА-ПРОЕКТА.md](../ПЕРЕДАЧА-ПРОЕКТА.md), раздел 5.
- **Резервный пул номеров.** Карусель в коде есть, второй транк в конфиге —
  нет. Понадобится, когда операторы начнут блокировать номера (CONCEPT.md §8.1).
