# socmon

Комплекс непрерывного телефонного социологического мониторинга с голосовым ИИ.

> **Начните с [ПЕРЕДАЧА-ПРОЕКТА.md](ПЕРЕДАЧА-ПРОЕКТА.md)** — как работает звонок,
> что готово, что осталось, как развернуть и подключить IP-телефонию.

Исследование рынка и правовой разбор — [RESEARCH.md](RESEARCH.md). Ссылки
вида «ТЗ §7.2» в коде — на пункты технического задания Заказчика (в открытую
копию оно не входит).

## Что уже работает

ARI, распознавание (GigaAM) и озвучка, база, взвешивание и индекс, кабинет,
выгрузки. Языковой модели в звонке нет по построению. Подробно —

## Анкета

Анкета Заказчика собирается из модулей: ядро и переменный блок лежат
отдельными файлами и подключаются всеми волнами, отличается только
последний модуль. Так формулировки ядра совпадают между волнами
посимвольно — иначе динамический ряд §3.1 рвётся незаметно, потому что
данные продолжают собираться.

```bash
uv run socmon check src/socmon/questionnaires/wave-social.yaml
uv run socmon play  src/socmon/questionnaires/wave-social.yaml
```

Перечень национальных целей в один хронометраж не помещается, поэтому
разложен на три модуля и опрашивается в разные волны.

## Запуск

```bash
uv venv --python 3.12 && uv pip install -e ".[dev]"
uv run socmon check          # проверить анкету перед запуском волны
uv run socmon play           # прогнать интервью вручную
uv run socmon wave           # сводка по волне на синтетическом массиве
uv run socmon voice render   # озвучить анкету (нужна группа voice)
uv run socmon voice check    # полнота озвучки и оценка длительности
uv run socmon play --voice   # интервью вслух
uv run socmon simulate       # прогнать волну целиком без Asterisk
uv run socmon contacts import база.csv              # загрузить номера
uv run socmon useradd ivanov "Иванов И." customer   # завести доступ
uv run socmon serve          # поднять кабинет на 127.0.0.1:8000
uv run socmon export --out out   # оперативный пакет и отчёт
```

Для PDF нужен LibreOffice; без него `--pdf` честно откажется, а не отдаст
молча один DOCX:

```bash
brew install --cask libreoffice
```

Для тестов и миграций нужен PostgreSQL:

```bash
brew install postgresql@17 && brew services start postgresql@17
createdb socmon_dev && createdb socmon_test
uv run alembic upgrade head
uv run pytest && uv run mypy && uv run ruff check .
```

Тесты, которым нужна база, пропускаются, если её нет; ядро и доменные
правила проверяются всегда.

## Ключи

Номера шифруются и ищутся по слепому индексу. Оба ключа — только из окружения:

```bash
export SOCMON_PHONE_INDEX_KEY=$(openssl rand -hex 32)   # менять нельзя без пересчёта базы
export SOCMON_PHONE_ENC_KEY=$(openssl rand -hex 32)
```

## Принципы, от которых не отступаем

* **Языковой модели в звонке нет.** Ход разговора определяют граф анкеты и
  грамматики узлов. Не разобрали — переспросили один раз и поставили код
  «нераспознанная речь», а не догадку (ТЗ §8.2).
* **Молчание никогда не читается как согласие** (ТЗ §8.2).
* **Все завершения — утверждённые.** Робот не импровизирует прощание: на каждый
  исход в анкете есть терминальный узел с согласованной формулировкой (ТЗ §8.1).
* **Правка формулировки меняет версию анкеты.** `version_id` — хеш содержимого,
  «та же анкета, но чуть-чуть другая» технически невозможна (ТЗ §7.3).
* **Отказ, затруднение и нераспознанная речь — три разных кода**, а не один
  пропуск (ТЗ §5.3).
* **Контуры разделены схемами PostgreSQL.** В `survey` нет ни одного столбца,
  по которому можно выйти на абонента; связь живёт единственной таблицей
  `contact.identity_link` под отдельными правами (ТЗ §14.2).
* **Веса не видят ответов.** В расчёт весов передаются только признаки
  структуры выборки. Подбор весов с оглядкой на результат — подгонка,
  прямо запрещённая ТЗ §5.1, и здесь она невозможна по сигнатуре.
* **Доверительные интервалы считаются по эффективному объёму выборки**,
  а не по фактическому: взвешивание не бесплатно, и его цену видно
  в каждой оценке (ТЗ §5.2).
* **Пропуски не подменяются средними.** Отказ и затруднение выпадают из базы
  показателя; замена серединой шкалы требует имени согласовавшего (ТЗ §12).
* **Методика расчёта индекса сворачивается в хеш** и уходит в выгрузку рядом
  с числом (ТЗ §12, воспроизводимость).
* **Порядок обзвона случаен, но воспроизводим.** Он выводится из зерна
  загрузки и слепого индекса: случаен по отношению к любому признаку
  абонента (§4.2) и восстанавливается по зерну для проверяющего (§5.1).
  `ORDER BY random()` не годится — он даёт новый порядок на каждый запрос.
* **Стоп-лист переживает новую поставку.** Затереть отметку значило бы
  позвонить человеку, который просил больше не звонить (§6.2).
* **Дубли в файле и совпадения с базой считаются раздельно.** Первое говорит
  о качестве файла, второе — о пересечении поставок.
* **Анкета привязывается только к черновику волны.** Подменить её посреди
  волны значит получить половину интервью по одной редакции вопросов
  и половину по другой — никакая версия этого уже не разъяснит.
* **Не прошедшая проверку анкета не сохраняется.** Иначе волну можно
  запустить с графом, из которого нет выхода.
* **Утверждение привязано к идентификатору версии.** Правка формулировки
  даёт новый идентификатор, и утверждение обнуляется вместе с ним —
  иначе «утверждённая анкета» означала бы что угодно (ТЗ §7.3).
* **Волна закрывается и не открывается обратно.** Внутрь идущей волны нельзя
  досыпать номера: рамка выборки перестанет соответствовать той, по которой
  считались веса. «Вечная кампания» из блюпринта VOIF у нас невозможна
  по построению.
* **Запуск волны требует полной готовности, и система показывает, чего
  не хватает.** Запустив волну с устаревшей озвучкой, мы обзвоним тысячу
  человек не тем вопросом.
* **Без эталонных распределений аналитика отказывается считать.** Показать
  невзвешенные цифры как взвешенные — худшее, что можно сделать; отказ
  здесь важнее результата (ТЗ §5.4).
* **Отметка «проверено» не подменяет модельный вывод.** Проверяющий
  подтверждает разметку, но она остаётся модельной: §11.3 требует, чтобы
  автоматически сгенерированное оставалось отличимым от проверенного.
* **Выгрузка — событие журнала, а не просто чтение.** Массив уходит за
  пределы системы, и кто его забрал, должно быть видно (§14.2).
* **Право проверяется на маршруте, а не в шаблоне.** Спрятать ссылку в меню
  не защита: адрес можно набрать руками, и в системе с телефонными номерами
  это не теоретическое рассуждение.
* **Право видеть номер и право слушать запись — раздельные.** Уровни доступа
  тут не годятся: они соблазняют считать, что больший включает меньший,
  а дежурному оператору номер нужен, аналитику — нет, хотя аналитик «главнее».
* **Просмотр чувствительного журналируется наравне с изменением.** Кто и когда
  слушал запись разговора — строка в журнале (ТЗ §14.2, §13.4).
* **Классификатор тем — редактируемый файл, а не модель.** §11.2 требует,
  чтобы Заказчик его утверждал, правил и вёл по версиям; модель как чёрный
  ящик такому требованию не отвечает. У классификатора есть версия-хеш,
  и любая разметка несёт её рядом с собой (§11.3).
* **Неоднозначные упоминания не сливаются автоматически.** «Иванов» из двух
  интервью может быть депутатом и соседом; §7.5 запрещает объединять такие
  имена без ручной проверки, и система помечает их, а не догадывается.
* **Оценки тональности маркированы как модельные.** Каждый вывод несёт
  признак и оговорку: не диагностика и не основание для суждений
  о конкретном респонденте (§11.1).
* **Распознавание свободное, ограничение — на тексте.** GigaAM это
  end-to-end модель, грамматику в её декодер не подставить. Поэтому
  распознаём как есть, а варианты ответа проверяем грамматиками узла;
  не совпало — переспрос и код нераспознанной речи, а не догадка.
  Побочный выигрыш: сырой текст целиком уходит в ночной разбор.
* **Реплики озвучиваются заранее и привязаны к хешу своего текста.**
  Правка формулировки помечает запись устаревшей, и волну нельзя запустить,
  пока она не переозвучена. Иначе робот читает прошлую редакцию вопроса,
  а в массив пишется код по новой (ТЗ §8.1).
* **Рантайм не решает, что спросить.** Он озвучивает решение движка анкеты
  и передаёт ответ обратно. Исход интервью не выводится из состояния звонка:
  респондент, положивший трубку на середине, даёт прерванное интервью,
  а не «завершённое с обрывом».
* **Прерванный разговор сохраняется.** Ответы, данные до обрыва, — это данные,
  а не мусор; валидность решается правилами §5.3 отдельно.
* **Сбой при наборе не съедает попытку.** Контакт возвращается в очередь,
  иначе поломка транка израсходовала бы лимит попыток на номер (ТЗ §6.2).
* **Предохранитель считает только отказы инфраструктуры.** Занято и недозвон —
  нормальная жизнь обзвона, останавливать по ним волну нельзя.
* **Стадия звонка меняется только через машину состояний.** Прямая запись
  в обход запрещена конвенцией. Событие, невозможное по жизненному циклу,
  отвергается: «интервью завершено» из стадии набора пометило бы недозвон
  как состоявшееся интервью.
* **Повторная доставка события безобидна.** Уникальный идентификатор события
  провайдера гасит дубль, оптимистичная блокировка ловит конкурентную
  запись, а сторож закрывает зависшие звонки по времени — на случай, когда
  событий нет вовсе.
* **Имя провайдера не выходит за `telephony/`.** Проверка чистоты слоя:
  `grep -ri asterisk src/socmon --exclude-dir=telephony` должен молчать.
* **Достижимость считается по AAPOR**, а не по самодельной формуле.
  Публикуется RR3; RR5 приводится с оговоркой, что он систематически выше
  и «долей ответивших» не является (ТЗ §13.2).
* **Отчёт не пишет выводы за аналитика.** Разделы 1-9 содержат только фактуру,
  раздел выводов заполняет человек. Раздел без данных остаётся пустым
  с объяснением, а не заполняется предположениями (ТЗ §13.3).
* **Модельные выводы не смешиваются с первичными данными.** Кодирование
  открытых ответов пишется в отдельную таблицу, помечено как машинное
  ограничением базы и версионируется — перекодирование добавляет строку,
  а не переписывает старую (ТЗ §11.3).
